# 对话里的引用：指着一条回复、一个文件说话

> 状态：落地分三步（§11）。**第一步（bot）已做**：`ref` 块、`refList` 校验、三条路、`refBlock`、
> `e2e/references.mjs`。**第二步（Gateway + 界面）已做**：`refShapes` 透传、输入框上的引用条、
> 气泡悬停「引用」、预览面板「引用这个文件」、气泡里的卡与跳回、导出、老席位提示；
> e2e 在 `chat-fold`（折叠与壳）和 `gateway-chat`（透传）里各加了一条。第三步（桌面端发版）未动。

今天在对话框里，人要让 Bot「接着上面那段改」或者「把刚才那份表再加一列」，只有一条路：
把那段话、那个文件名**再打一遍**。本文给对话加一种输入——**引用**：点一下某条回复、
某个文件，它就以结构化的形式跟着下一条消息一起发出去，界面上画成一张卡，进模型时
渲染成一段话。

相关：`@` 点名是同一类东西、同一套管道（[session/types.ts](../bot/src/session/types.ts) 的
`mention` 块），本文处处照它的样子做；上下文怎么装配见
[context-assembly.md](./context-assembly.md)；文件药丸的来历见
[file-terminal-tools.md](./file-terminal-tools.md) §2 第 5 条。

---

## 1. 为什么

**一、长会话里「上面那条」指不清。** 一个 Bot 一条长会话，只增不减。Bot 一下午回了二十
条，人想对其中第七条说「这个方案不行，按第三条路线重写」，今天得把第七条的要点复述一
遍——复述得不准，模型就对着一个它没说过的版本改。模型那边也一样：历史里二十条回复，
「上面那段」到底是哪段，它是猜的。

**二、文件只能「提」不能「指」。** 产出文件在气泡底下是一颗药丸，上传的附件也是；但
它们只能**看**，不能**作为下一句话的对象**。人要说「把这份 docx 的第二节翻成英文」，
得把 `uploads/s-0189…/合同.docx` 这串路径抄进输入框——而那串路径是模型写出来的，人
根本不该见到（[fileOutBlock](../bot/src/agent/index.ts:3850) 教模型别让用户碰路径，结果
用户自己要指一个文件时反而只能碰路径）。

**三、上传已经是结构，引用也该是。** 人传的附件在正文里是一段我们自己拼的
「我上传了文件，在工作区里：」（[composeChatBody](../gateway/ui/chat.js:8293)），界面再按
文本认回来（[splitUploads](../gateway/ui/chat.js:568)）。那段注释自己就写了：敢按文本认，
是因为格式是我们定死的。引用如果也走这条路，就要再定一种文本格式、再写一个认回来的
解析器，而且**引用的是模型写的话**——那段话里什么都可能有，按文本切一定散架。
`mention` 块那条注释把道理讲透了：**落盘是结构，进模型是话**。引用照抄。

**不为什么做：** 不是为了做成 Slack 那种「线程」。一个 Bot 一条会话、顺着往下走，是这个
产品定下的形状（[chat-commands.md](./chat-commands.md)）；引用只是给这条线上的某一句话
加一个指针，不开分叉。

## 2. 目标与非目标

**做成：**

1. 对话里任一条 **Bot 回复**（也包括自己发过的消息）能被引用：鼠标停上去有一个「引用」，
   点了之后这条消息的摘录挂到输入框上方，随下一条消息发出
2. 对话里露过面的任一个 **工作区文件**——人传的附件、工具报出来的产出、正文里被换成
   药丸的那些——能被引用：预览面板里一个「引用这个文件」，点了同样挂到输入框上
3. 发出去的那条消息在气泡里**带着引用卡**：引用的回复画成一张可点的卡（点了跳到原消息），
   引用的文件画成原来那颗药丸。翻到昨天那条，仍然看得出「当时指的是哪条、哪个文件」
4. 进模型的是一段**边界清楚**的话：被引用的回复**全文**（有上限）、被引用文件的路径；
   被压缩掉的旧回复也拿得到全文（这正是引用比「上面那条」强的地方）
5. 图片文件被引用时，模型**看得到图**，走现有的 `images` 那条路
6. 排队（`@` 那种）、插话（Bot 在跑时发的那一条）两条岔路都带着引用，不丢

**先不做：**

- **引用 Bot 回复里的某一段。** 选中一段文字再引用，要在 Markdown 渲染结果和源文本之间
  对位置，`syncMd` 那套按块增量渲染的结构里做不干净。先整条。人要指一段，引用整条再
  在正文里说「第二节」，模型分得清
- **引用工具痕迹（某一次 bash、某一次 web_extract 的结果）。** 它们是药丸不是消息，而且
  结果正文动辄几 KB。模型自己有 `history_*` 能翻（[tools/history.ts](../bot/src/tools/history.ts)）
- **Telegram 那头的「回复某条」。** Telegram 的 `reply_to_message` 今天已经收下来了
  （[channels/telegram.ts:376](../gateway/src/channels/telegram.ts:376)），但只用在转人工的
  回单上；把它接成这里的引用需要「Telegram message_id ↔ 会话 seq」那张表，今天没有。
  数据模型给它留了位置（§4.1 的 `seq` 可空），见 §12
- **`@` 选单里选文件。** 打 `@` 搜文件名是更快的手，但 `@` 选单今天是连接器的
  （[paintMentionPick](../gateway/ui/chat.js:8124)），混进文件要先把选单分组。第一版只给
  预览面板那一个入口：药丸、正文里的行内路径、右栏「工作区文件」三处点开走的都是同一个
  预览（`data-act="chat-preview"`），一个按钮三处都覆盖到
- **跨会话、跨 Bot 引用。** `history_*` 那条「只看当前会话」的理由在这里同样成立

## 3. 人怎么用

**场景一：改方案。** Bot 回了三条候选方案。人把鼠标停在第二条上，点「引用」，输入框上方
出现一张小卡：「Bot · 14:32 · 方案二：先把订单表拆成…」。人打「这条按季度而不是按月，
重写」，回车。气泡里这条消息顶上带着那张卡；Bot 回的是对第二条的改写，不用再猜。

**场景二：接着处理文件。** Bot 生成了 `报表/二季度.xlsx`，气泡底下一颗药丸。人点开预览，
面板右上角「引用这个文件」，面板收起、输入框上方多了那颗药丸。人打「加一列同比」。
Bot 收到的是 `[引用文件：报表/二季度.xlsx]` + 那句话，直接 `office_unpack` 去改。

**场景三：翻旧账。** 上周传的合同已经被上下文压缩吃掉了，人往上翻到那条自己发的消息，
附件药丸还在。点开 → 引用 → 「这份合同的付款条款是什么」。文件还在工作区里，模型读
就是了；要是文件已经被人从右栏删了，模型收到的那行会写明「文件已不在工作区」，它会
说「那份文件已经删了」，而不是去工作区里瞎找。

**场景四：Bot 在跑，先把引用挂上。** 一轮正跑着，人引用了上一条回复打「等会按这条再来
一遍」。这条走插话（steer）那条路，引用跟着一起进当前这一轮的消息列表，并且照旧落一条
`user/message`——刷新页面之后那张卡还在。

**一条消息最多 10 个引用**（和图片、`@` 同一个上限），引用的回复和引用的文件混着算。
输入框上方每张卡都有 ×，发送失败时和草稿、`@` 一起原样退回来。

## 4. 数据模型

### 4.1 新的内容块 `ref`

在 [session/types.ts](../bot/src/session/types.ts) 的 `ContentBlock` 加一种：

```ts
/**
 * 用户指着说话的一个东西（v6 起）。两种：一条消息，或一个工作区文件。
 *
 * **存结构，不存一句话。** 道理和 mention 块一字不差。另一条理由是这里独有的：
 * 引用的回复**全文不落在这里**——它已经在同一份 JSONL 里了，按 seq 回去读；
 * 这里只留一段摘录，给界面画卡用。
 */
| {
    type: 'ref'
    kind: 'message'
    /** 被引用那条 user/message 或 assistant/message 事件的 seq。外部渠道接进来时可能没有。 */
    seq?: number
    role: 'user' | 'assistant'
    /** 原文开头，≤ 300 字。界面画卡、以及 seq 找不到时的退路。 */
    excerpt: string
    /** 原消息的时间，渲染给模型时写进去。 */
    time: number
  }
| {
    type: 'ref'
    kind: 'file'
    /** 相对工作区根目录。 */
    path: string
    name: string
  }
```

`SESSION_FORMAT_VERSION` 5 → 6。和 `mention` 当年一样：老事件一条不改、不用迁移；
老版本读到不认识的块类型会跳过（`textFrom` 对未知类型返回空串），退化成「这条消息没带
引用」。加版本号是为了让「这份日志里可能有 ref 块」这件事有个明确的记号。

**为什么 `seq` 而不是 `message.id`。** `seq` 是会话内单调递增、界面上每一块都已经带着
（`fold` 出来的块有 `seq` 字段，[chat.js:664](../gateway/ui/chat.js:664)）、`history_*` 和
`session/compact` 都用它定位。`message.id` 是个 UUID，界面今天根本没拿到它。

**为什么 `excerpt` 要存。** 界面画那张卡的时候，被引用的那条未必在已经加载的那几页里
（历史按 20 轮一页拉，[hydrateChat](../gateway/ui/chat.js:1249)）；`/clear` 之后它更是
不画了。不存摘录，卡就只能画成「引用了第 1532 条」。300 字是「一眼认得出是哪条」的量，
不是给模型看的——模型看的是全文（§6）。

**为什么 `role` 要存。** 卡上要画是 Bot 说的还是自己说的，而这不能按 seq 回查——同上，
那条未必在手上。

### 4.2 消息里的顺序

`userBlocks`（[agent/index.ts:3535](../bot/src/agent/index.ts:3535)）今天的顺序是
点名 → 图片 → 正文。加上引用之后：**点名 → 引用 → 图片 → 正文**。引用排在图片前面，
是因为引用的图片文件会同时以 `image` 块进来（§5.2），两块挨着，渲染出来是
「[引用文件：x.png]」紧跟那张图。

## 5. 接口

### 5.1 `POST /runtime/sessions/:id/messages` 加 `refs`

请求体多一个数组，形状就是 §4.1 去掉 `type`：

```json
{
  "text": "这条按季度重写",
  "refs": [
    { "kind": "message", "seq": 1532, "role": "assistant", "excerpt": "方案二：先把订单表…", "time": 1791234567890 },
    { "kind": "file", "path": "报表/二季度.xlsx", "name": "二季度.xlsx" }
  ]
}
```

**Gateway 只认形状，不校验内容**（[routes/runtime.ts:1746](../gateway/src/routes/runtime.ts:1746)）。
`@` 之所以要在 Gateway 逐个校验，是因为「这把连接属不属于这个账号」只有 Gateway 知道；
而引用指的是这条会话自己的消息和这个工作区自己的文件，归属已经由
`seatTargetForSession` 定了。Gateway 做的是：截到 10 条、每项只透传认识的字段、
`excerpt` 截到 300 字。和 `images` 是同一个待遇。

**席位那边校验**（[web/index.ts:742](../bot/src/web/index.ts:742)），照 `imageRefs` 的样子
写一个 `refList`：

| 项 | 规则 | 不过怎么办 |
|---|---|---|
| `kind: file` 的 `path` | `ctx.workspace.resolve` 不越界 | **400**。路径是浏览器传上来的，这一层不做工作区边界就等于没有 |
| `kind: file` 的文件在不在 | 不查 | 落盘照落。文件在不在是**渲染那一刻**的事（§6），落盘时查了也挡不住之后被删 |
| `kind: message` 的 `seq` | 本会话里存在，且 type 是 `user/message` 或 `assistant/message` | **400**「引用的消息不存在」。seq 是界面从事件上抄的，对不上就是界面的 bug 或别的会话的 seq，收下只会落一条指向错处的记录 |
| `kind: message` 的 `excerpt` / `role` / `time` | 只截长度、只认两个 role | 不信浏览器那份：seq 对上了就从那条事件**重算** excerpt、role、time，浏览器给的只在 seq 缺失时用（§12 的渠道场景） |

**响应多一个字段 `refs: n`**（收下了几条）。界面靠它判断席位认不认这个字段：发了引用
但响应里没有 `refs`，就是老版本的席位，那条消息已经**不带引用地**发出去了——界面要
flash 一句「这个席位还不认引用，这条没带上（要更新 Bot 版本）」。这和「这个席位还不支持
列工作区文件」是同一个套路（[chat.js:5925](../gateway/ui/chat.js:5925)）。

### 5.2 引用的图片同时走 `images`

界面侧：引用的文件如果是模型看得了的图（`MODEL_IMAGE` 那张表，
[chat.js:8303](../gateway/ui/chat.js:8303)），**同时**放进 `images`。这样它既有「这是用户指着
的那张图」这一行字，又有真正的视觉输入。席位不用为引用另开一条喂图的路。

本地 Bot（桌面端）走 `data.js` 的 `localRoute` 改道到 127.0.0.1，请求体一样，不用动。

### 5.3 排队与插话

- `enqueue`（[agent/index.ts:1083](../bot/src/agent/index.ts:1083)）的 `QueuedMessage` 加
  `refs`，`drainQueue` 跑的时候原样带进 `runGuarded`
- `steer`（[agent/index.ts:1193](../bot/src/agent/index.ts:1193)）加 `refs` 参数，
  `userBlocks` 带上，落的那条 `user/message` 也带上
- `send` / `runTurn` / `failBeforeTurn` 把 `refs` 一路传到 `userBlocks`。**三处落
  `user/message` 的地方一处都不能漏**——漏一处，那一条路发出去的消息刷新之后卡就没了

## 6. 进模型：渲染成话

翻译只在一处：`textFrom`（[agent/index.ts:3490](../bot/src/agent/index.ts:3490)），和
`mention` 一样。但 `ref` 的渲染要读 JSONL 和工作区，所以 `textFrom` 从纯函数变成拿一份
「引用解析结果」的函数——解析在 `toAgentMessages` 开头做一次，按 seq 和路径查好，
`textFrom` 只负责拼。**这一轮以后的重放也要一致**（不变量 7）：解析时文件不在，渲染出
「已不在工作区」；下一轮文件又回来了，渲染就变了——这是对的，模型要看的是**现在**。

渲染格式，照 `[本轮指定：…]` 那种方括号风格：

```
[引用你 2026-10-08 14:32 的回复]
方案二：先把订单表拆成两张……（全文）
[引用结束]

[引用文件：`报表/二季度.xlsx`]

这条按季度重写
```

规则：

- **引用的回复给全文**，上限 4,000 字。超了截断，末尾加一行
  「（全文 12,340 字，这里只有开头；要看全可以 history_read 2026-10-08 14:30 前后）」。
  给全文而不是摘录，是因为引用的意义就是**消除歧义**——摘录只能让模型去历史里找，而
  历史可能已经压缩了。被引用的那条还在上下文里时全文会重复一遍，4 KB 以内的重复不值
  一提
- 全文从哪来：按 seq 读那条事件的 `message.content`，取 `text` 块拼起来；助手消息里的
  `reasoning` 和 `tool-call` 块**不要**。seq 找不到（§12 的渠道场景、或 `/clear` 之后
  用户硬发）退回 `excerpt`，并写成「[引用你之前的回复（只有开头）]」
- 自己发过的消息：「[引用用户 … 的消息]」
- **引用的文件只给路径**，不读内容。模型有 `read_file` / `office_unpack` / `look`，让它
  自己决定读多少。文件已经不在：「[引用文件：`x.xlsx`（已不在工作区）]」
- 系统提示词里加一段 `refBlock()`，**只在这一轮的消息带 `ref` 块时**才加（条件加载的
  理由和 `fileOutBlock` 一样），内容三句话：方括号里那段是用户指着的东西；指着的回复
  是你自己说过的，改它、不要重新发明；指着的文件按路径去读，别问「哪个文件」

## 7. 界面

全在 [gateway/ui/chat.js](../gateway/ui/chat.js)，样式进 `chat.css`。改了 `gateway/ui` 就要
发桌面端，这件事在 [desktop/README.md](../desktop/README.md) 开头写着。

### 7.1 发之前：输入框上方的引用条

- `state.chatRefs`：数组，和 `chatFiles` / `chatMentions` 并列。随 `chatDrafts` 按 Bot
  收起、切回来再摆出来（[chat.js:1542](../gateway/ui/chat.js:1542) 那两处）；发送失败走
  `returnDraft`（[chat.js:8372](../gateway/ui/chat.js:8372)）一起退回；`flushHeldSend`
  的「有没有东西可发」判断加上它
- 新的 `#chat-refs` 容器，摆在 `#chat-mentions` 上面，`paintChatRefs()` 画。消息引用画成
  一张卡：左侧一条竖线，第一行「Bot · 14:32」或「我 · 14:32」，第二行摘录一行截断；
  文件引用画成现有的 `sw-filechip`。每张都带 ×（`chat-ref-drop`）
- 上限 10；同一条消息、同一个文件不重复；超了 flash 一句
- `sendChat`（[chat.js:8397](../gateway/ui/chat.js:8397)）：请求体加 `refs`；引用的图片按
  §5.2 并进 `images`；`pending` 那条回执也带 `refs`，不然气泡会先没有卡、等事件回来再
  突然长出来（和 `mentions` 那条注释说的是同一件事）

### 7.2 从哪儿点出来

**消息。** 每条气泡（`rowShell`，[chat.js:3672](../gateway/ui/chat.js:3672)）加一排悬停才
出现的动作 `.sw-msg-acts`，第一版只有一个「引用」（`chat-ref-msg`，`data-seq` 从块上拿）。
正在流式输出的那条**不给**：它还没有 `assistant/message`，seq 指的是第一条 chunk，发出去
席位会按 §5.1 判 400。`pending` 的用户消息同理不给。

**文件。** 预览面板（[chat.js:7320](../gateway/ui/chat.js:7320) 那排按钮）在「下载」旁边加
「引用这个文件」（`chat-ref-file`）。点了之后：挂到 `chatRefs`、关掉预览、输入框聚焦。
三条路都经这里：气泡底下的药丸、正文里被换成药丸的行内路径、右栏「工作区文件」的行。

**为什么不在药丸上直接给**：药丸是一个按钮，点了就是预览；再塞一个小按钮进去要么挤要么
要右键，而右键在桌面端壳子里和触屏上都不自然。预览面板是人「确认过是这个文件」的地方，
引用放在那儿顺手。

### 7.3 发出去之后：气泡里的卡

`fold` 的用户块多一个 `refs`（从 `message.content` 里挑 `ref` 块，照 `messageMentions`
的写法）。`updateRow` 在 `.sw-shots` 那一段旁边再放一个 `.sw-refs` 条：

- 消息引用的卡可点（`chat-ref-jump`）：按 `data-seq` 找已加载的那条，`scrollIntoView` +
  一秒高亮。没加载到就 `loadOlderChat` 往前翻，最多翻 5 页；还没有就 flash「那条消息
  不在这里了」（`/clear` 过、或者太久远）
- 文件引用就是 `fileChipHtml`，点了预览——和气泡底下的产出药丸是同一个东西
- `knownFiles`（[chat.js:3140](../gateway/ui/chat.js:3140)）把 `refs` 里的文件也收进名册：
  人引用过的文件，正文里再出现文件名就该能点
- 「复制全文」「导出 Markdown」（[chat.js:5283](../gateway/ui/chat.js:5283) 那段）：用户消息
  前面加「> 引用 Bot 14:32：摘录」和「- 引用 `路径`」两种行

### 7.4 一眼看得出的几条

- 引用条里的卡和气泡里的卡长一个样，只是前者带 ×
- 卡上**不画全文**，一行摘录。全文在原消息那儿，点卡就到
- 引用了自己发的消息：卡上写「我」不写名字——和头像上的首字母是一个口径

## 8. 边界与异常

| 情况 | 行为 |
|---|---|
| 引用的回复被 `session/compact` 压掉了 | 模型照样拿到全文（§6 按 seq 读 JSONL）。这是引用最值钱的场景 |
| `/new` 之后引用 `/new` 之前的回复 | 允许。界面上那条还看得见；模型侧那条不在上下文里，全文随引用进来——正好 |
| `/clear` 之后 | 之前的消息界面上不画，自然点不到。硬发（老标签页）→ seq 仍存在于 JSONL，席位照收；卡点了跳不到，flash |
| 引用的文件被人从右栏删了 | 落盘照落；渲染成「已不在工作区」（§6） |
| 引用的文件路径越界 | 400，草稿退回，flash 错误原文 |
| 引用了正在输出的那条 | 界面不给按钮（§7.2） |
| 席位是老版本 | 消息**不带引用**发出去，界面 flash「要更新 Bot 版本」（§5.1）。不挡消息：用户那句话没有错 |
| Bot 在跑、这条带 `@` | 走排队，`QueuedMessage.refs` 跟着；dock 里那行也画卡（§5.3） |
| Bot 在跑、这条不带 `@` | 走插话，`steer` 带 `refs`，落的 `user/message` 带 `ref` 块 |
| 引用 10 个以上 | 界面挡；席位截到 10 |
| 同一张图既上传又引用 | `images` 去重按 path |
| 对话审计（conversation-audit） | 它读的是 `textFrom` 之后的话，看到的就是 §6 那段。不用改 |

## 9. 兼容与发版

- **JSONL**：版本号 5 → 6，不迁移。老 bot 读新日志：跳过 `ref` 块
- **席位 ↔ Gateway**：新 Gateway 发 `refs` 给老席位 → 字段被忽略，响应里没有 `refs` →
  界面提示。老 Gateway 对新席位 → 根本发不出 `refs`，无事
- **桌面端**：界面打在包里，§7 落地之后要发一版桌面端
- **渠道**（Telegram）：不受影响，`ref` 块不会从渠道进来（§12 之前）

顺序：**先发 bot，再发 Gateway/界面，最后桌面端**。反过来会有一段时间所有人都看到
「要更新 Bot 版本」。

## 10. 测试

`e2e/references.mjs`，照 `e2e/mentions.mjs` 的搭法：

1. 发一条带 `message` 引用的消息 → JSONL 里那条 `user/message` 有 `ref` 块、`seq` 对、
   `excerpt`/`role`/`time` 是席位重算的；探针 provider 收到的用户文本里有
   `[引用你 … 的回复]` + 原文全文 + `[引用结束]`
2. 先把历史压缩掉（照 `e2e/compact.mjs`），再引用压缩区间里的一条 → 探针仍收到全文
3. 引用一个 >4,000 字的回复 → 截断 + 那行「history_read」提示
4. `file` 引用路径越界 → 400；引用不存在的文件 → 落盘成功，探针收到「已不在工作区」
5. `message` 引用的 seq 不存在 / 指向 `tool/result` → 400
6. 引用一张 png 且 `images` 带它 → 探针收到 image 块 + 「[引用文件：…png]」
7. Bot 在跑时发带引用的插话 → `user/message` 落了、带 `ref` 块
8. 响应里有 `refs: n`
9. 界面：`chat-fold.mjs` 加一段，`fold` 出来的用户块带 `refs`；`gateway-chat.mjs` 加一段，
   Gateway 把 11 条截成 10 条、陌生字段不透传

## 11. 分步落地

PR 的 base 是 `develop`。

**第一步，bot（一个 PR）。** `types.ts` 加块 + 版本号；`userBlocks` / `textFrom` /
`toAgentMessages` 的解析；`refList` 校验 + 路由收 `refs` + 响应 `refs: n`；
`enqueue` / `steer` / `send` 三条路；`refBlock()`；e2e 1–8。**这一步发出去之后席位就认
引用了，界面还没有入口，没人用得到，但不会坏。**

**第二步，Gateway + 界面（一个 PR）。** 代理透传；`chatRefs` 状态与草稿收放；引用条；
气泡悬停「引用」；预览面板「引用这个文件」；气泡里的卡与跳转；导出格式；老席位提示；
e2e 9。

**第三步，桌面端。** 跟着 gateway/ui 发一版。

## 12. 以后

- **Telegram 的 `reply_to_message` 接成引用。** 数据模型已经留了 `seq?` 可空、`excerpt`
  必有：渠道那头把 `replyToText` 装成 `{kind:'message', role:'assistant', excerpt}` 送进来，
  模型至少知道用户在回哪一条。要对上 seq，得在发出 Telegram 消息时记下
  `message_id → seq`，那是渠道那边的一张小表
- **`@` 选单里搜文件。** 把 `knownFiles` 那份名册喂给选单，分「连接」「文件」两组。
  比点开预览再点引用少两步，对键盘党尤其值
- **引用一段。** 等 Markdown 渲染和源文本的位置对应做稳了再说
- **Bot 自己引用。** 模型回答时指着某条历史说「按你 14:32 那条」，界面也能画成卡——
  需要模型在正文里写出一种约定（比如 `[[seq:1532]]`），像行内路径换药丸那样认回来。
  先不做：那是在教模型一种新语法，收益要看用起来之后人到底多常翻旧账
